# Демонстрация backend

Все пользователи и задания синтетические. После `docker compose up --build` доступны Swagger UI на `http://localhost:8000/docs` и восемь ролей: `admin`, `student`, `content`, `expert1`, `expert2`, `senior`, `auditor`, `bi`. Пароль задаётся через `SEED_PASSWORD` в `.env`. Seed автоматически импортирует математику и физику, создаёт варианты и назначения.

| Шаг | Действие и ожидаемый результат |
|---|---|
| 1 | Войти как `content` через `POST /api/v1/auth/login`; использовать access token в Swagger Authorize. |
| 2 | Передать `examples/kim/math-valid.zip` в `POST /kim-imports/validate` как `application/zip`, затем в `/kim-imports`. Показать checksum и протокол. Повтор не создаёт новую версию. |
| 3 | Показать `/kim-packages` и историю `/kim-packages/{id}/versions`; отдельно импортировать физику. |
| 4 | Создать и опубликовать вариант, затем как `admin` создать экзамен и назначить `student`. ID заданий/варианта берутся из ответа импорта; ID участника — из `/users/me` под student. |
| 5 | Как `student` вызвать `/exams/{id}/sessions` дважды: ID сессии совпадает. Ответ содержит UTC deadline, задания и счётчики аудио. |
| 6 | Сохранить ответ с `expectedRevision: 0` и `Idempotency-Key: demo-save-1`. Повтор идентичен; иной ключ со старой ревизией даёт 409. |
| 7 | Запросить аудио дважды с разными ключами; обе одноразовые ссылки действуют. Третий запрос при лимите 2 даёт 409. |
| 8 | Выполнить `/sessions/{id}/submit`; новая запись ответа запрещена. Закрытые задания проверены, развёрнутые попадают в очередь. |
| 9 | Как два эксперта по очереди claim → scores → finalize. Один эксперт не может выполнить обе проверки. |
| 10 | При расхождении `senior` получает обезличенную работу и выставляет `scores` по всем критериям в `/reviews/disputes/{id}/resolve`. |
| 11 | `student` получает результат: отметка 2–5, статус проверки, детализация и версия правил. При недостатке геометрии возвращаются 2 и `GEOMETRY_MIN_NOT_MET`. |
| 12 | `admin` пересчитывает результат; история сохраняет предыдущую версию. `auditor` читает события, `bi` получает выгрузку без логинов и текстов ответов. |
| 13 | Показать `openapi.yaml`, отчёт покрытия и `docs/traceability.md`. Нагрузочные показатели показывать только после реального измерения. |

## Без внешней сети

После однократной установки зависимостей выполните:

```bash
bash scripts/demo_offline.sh
```

Скрипт создаёт временную SQLite БД, применяет миграции, импортирует синтетические пакеты, проверяет OpenAPI и запускает сквозные тесты. Данные удаляются после завершения. Docker и интернет не требуются. Это резервная демонстрация корректности; она не подтверждает производительность PostgreSQL.

## Резервное выступление на 60–90 секунд

Первые 15 секунд: открыть README и ER-диаграмму, назвать роли и границы backend. Следующие 20 секунд: запустить offline-скрипт и показать проверки импорта, ревизий, аудио и независимой экспертизы. Следующие 20 секунд: открыть тест сквозного результата и объяснить геометрический порог и сохранение старой версии при пересчёте. Последние 15–30 секунд: показать OpenAPI, матрицу требований и честно назвать ещё не измеренные эксплуатационные NFR. Видеозапись не входит в поставку; этот сценарий воспроизводится локально.

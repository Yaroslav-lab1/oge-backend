# Нагрузочное тестирование

## Сценарии и подготовка

`load/k6.js` содержит три режима: `starts` создаёт 300 сессий за 60 секунд, `state` читает состояние при 300 одновременных VU, `save` сохраняет ответы с частотой 50 RPS. Метрики `oge_session_read_ms` и `oge_answer_save_ms` измеряют только целевые операции; логин и создание сессии в них не включены. Порог 5xx — меньше 1%. Каждый VU использует отдельного назначенного синтетического участника.

Нужны запущенный `docker compose up --build`, установленный k6 и пароль для нагрузочных пользователей. Подготовьте отдельный cohort для каждого запуска:

```bash
read -sr LOAD_PASSWORD && export LOAD_PASSWORD
docker compose exec -T -e LOAD_PASSWORD api python -m scripts.seed_load --prefix warm01 --students 300
EXAM_ID=<examId из предыдущего вывода>
k6 run -e MODE=state -e BASE_URL=http://127.0.0.1:8000 \
  -e EXAM_ID="$EXAM_ID" -e LOAD_PREFIX=warm01 -e LOAD_PASSWORD="$LOAD_PASSWORD" \
  --summary-export=work/state-warm01.json load/k6.js
```

Для `starts` и `save` замените `MODE`; для каждого запуска используйте новый `--prefix` и такое же `LOAD_PREFIX`. Перед запуском создайте каталог `work/`. Сценарий `starts` требует новых назначений для проверки реальных стартов, а повтор уже созданного cohort меняет смысл измерения. Для `state` и `save` начальная инициализация VU создаёт сессию, но целевые Trend-метрики начинаются после неё.

Проведите 3 прогрева и 5 основных запусков для каждого режима, в одинаковой конфигурации стенда. Сохраняйте вывод k6 и Prometheus, а также параметры CPU/RAM, число экземпляров API, размер БД и сетевую задержку. По пяти основным запускам сообщайте p50/p95/p99 целевых Trend-метрик, фактический throughput, долю 5xx, `dropped_iterations` и число сохранённых ревизий. Дополнительно перезапустите один API-экземпляр после подтверждённых сохранений и сравните ответы до/после.

# Резервное копирование и восстановление

Источником истины является PostgreSQL 16. Контейнер `db` хранит данные в именованном томе `postgres_data`; удаление тома уничтожает данные. Архивы нужно хранить вне хоста БД, шифровать и ограничивать доступ. Секреты и архивы не помещаются в Git.

## Учебный стенд

Разовый логический архив можно создать командой:

```bash
docker compose exec -T db sh -ec 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc' > oge.dump
```

Для восстановления сначала остановите запись в API и подготовьте пустую БД. Пример восстановления в отдельную БД для проверки:

```bash
docker compose exec -T db sh -ec 'createdb -U "$POSTGRES_USER" oge_restore'
docker compose exec -T db sh -ec 'pg_restore --exit-on-error --single-transaction --no-owner -U "$POSTGRES_USER" -d oge_restore' < oge.dump
```

Автоматический тест `make backup-restore` делает архив, восстанавливает его во временную БД, сравнивает количество строк в ключевых таблицах и удаляет временные файлы и БД. Он возвращает измеренное время выполнения. Проверка не заменяет пробный запуск API на восстановленной БД и проверку целостности отдельных ответов; перед приёмкой стенда их следует выполнить отдельно.

## Целевые RPO и RTO

ТЗ задаёт RPO ≤ 5 минут и RTO ≤ 30 минут. Для RPO одного периодического `pg_dump` недостаточно: на учебном стенде требуется базовый архив плюс непрерывная архивация WAL или сопоставимый журнал изменений на отдельное хранилище. Для RTO подготовьте автоматизированное развёртывание, восстановите последний архив и WAL, затем выполните `alembic current`, `GET /api/v1/health/ready` и сверку контрольных строк. Периодически выполняйте полный пробный restore и фиксируйте время/потерянные транзакции.

На текущем хосте Docker daemon недоступен. Протокол реального PostgreSQL restore и подтверждение RPO/RTO пока отсутствуют; `scripts/backup_restore_test.sh` готов для запуска на стенде.

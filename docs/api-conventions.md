# Соглашения API

- Базовый путь: `/api/v1`; JSON в UTF-8; даты — ISO 8601 с UTC offset или `Z`.
- Успешный ответ содержит `X-Correlation-ID`. Любая ошибка имеет вид `{"code":"...","message":"...","details":{},"correlationId":"uuid"}`. Поле `details` не содержит stack trace, SQL и секретов.
- Защищённые маршруты принимают `Authorization: Bearer <access JWT>`. Время жизни access не более 15 минут, refresh не более 7 суток.
- `Idempotency-Key` — печатная ASCII строка до 255 символов. Для поддерживаемых мутаций повтор того же ключа и тела возвращает прежний результат; другой запрос с тем же ключом возвращает `409`.
- `PUT /sessions/{id}/answers/{taskId}` принимает `{"raw": <JSON>, "expectedRevision": N}`. Первый ответ требует `N=0`. При конфликте `409` содержит `currentRevision`; клиент перечитывает состояние и решает, отправлять ли новую ревизию.
- `taskId` в маршрутах сессии обозначает `TaskVersion.id`, то есть снимок задания, выбранный опубликованным вариантом.
- Ошибки валидации — `422`, отсутствие токена — `401`, запрещённый доступ — `403`, отсутствие объекта — `404`, конфликт состояния — `409`, ограничение входа — `429`.
- В OpenAPI есть описания маршрутов и схемы входных данных. Сохранённый контракт генерируется командой `make openapi`.

Состояния сессии: `CREATED → ACTIVE → SUBMITTED | EXPIRED → CHECKING → COMPLETED`; отдельно `CANCELLED`. Сервис создаёт сессию сразу в `ACTIVE`; промежуточные состояния оставлены в схеме для совместимости и расширения.
